# Library transaction runtime

The initial five release transactions ran in WSL. Three returned STILL_BLOCKED because the coordinator omitted distinct inherited FH review obligations. A fresh scoped review and three additional releases were required; runtime switching does not replace these duties.

Repeated path and hash checks on the mounted filesystem were slow. The later transactions used a private MSYS POSIX Python with /mnt/f and /mnt/c mapped to the same existing Windows drives. The three plugin modules stayed byte-identical; no verifier function, journal, immutable prompt or source binding was patched. verification.json records actual read-only revalidation of the original 45-input math review with a result identical to the WSL receipt, plus the observed imported module hashes. This is coordinator execution provenance, not an operating-system sandbox or another mathematical proof.

The package came from the [official MSYS2 Python package](https://packages.msys2.org/packages/python?variant=x86_64). source.json records the downloaded package SHA256 and copies of existing bundled DLLs. pyyaml-source.json binds the existing WSL PyYAML 6.0.3 pure Python sources copied unchanged to the private runtime. No installed runtime was modified; runtime binaries are retained locally, not redistributed here. The isolated child PATH chooses the private interpreter and standard library; -B/-I/-S and a private unused pycache prefix avoid ambient startup hooks and prior project bytecode.

The plain Windows runtime was rejected because it changed the absolute path used by the frozen prompt. Early POSIX startup selected an unrelated Python prefix through the ambient PATH; the private child PATH corrected it before library operations. A concurrent launch was refused by the existing writer.lock. The then-running supplemental WSL helper was gracefully interrupted inside read-only review validation, before request append; transition-completion.json preserves the actual exit130/KeyboardInterrupt, and before/after records verify unchanged journal bytes and released lock. A missing legacy YAML parser was also rejected before append, then supplied by the source-identical private copy. These failures are not successful operations.

native-operations.jsonl begins after supplemental packet preparation and records actual later dispatch/receipt/release/query helper exits and their source hashes. It does not retroactively claim coverage of earlier calls. The current graph state is established separately by library-final.json, default-query.json and the immutable correction receipts. Full numerical and Lean executions used their separately recorded environments and are not rerun or reclassified by this library-only transition.
